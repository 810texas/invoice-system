# 智能发票报销审核系统

以 **OCR 自动识别**替代手工录入、以 **规则化预审**统一审核口径的报销审核系统，构建「机器预审 + 人工终审」的人机协同流程。

**本期核心目标**

1. **自动填单** —— 批量上传发票影像 → OCR 提取字段 → 自动填入报销单，人工只做确认与修正
2. **规则拦截** —— 提交时硬拦截重复报销与金额不符，预警抬头错误与预算超标
3. **全程留痕** —— 字段修改痕迹与审核决策轨迹全程可追溯

**当前状态**：核心闭环已端到端跑通，自动化验收 **43/43**（端到端）+ **32/32**（演示）+ **50/50**（OCR 字段提取层）+ **14/14**（PDF 拆页）全部通过；
**真实 PaddleOCR 已接入**（本地 CPU 推理，影像不出本机，热态约 0.5 秒/张）；**支持 JPG/PNG/PDF 上传**（PDF 自动拆页，每页一张发票）。
尚未闭环的主要是：真实票样 100 张 P95、OCR 异步化、写接口限流、费用类别强制、前端生产构建。

技术栈：Vue 3 + Element Plus ｜ FastAPI + SQLAlchemy 2.0 ｜ MySQL 8.0（14 张表）｜ OCR provider：`mock` / `paddle`（本地 PaddleOCR）

## 快速开始

```bash
# 1. 建库（MySQL 8.0）
#    CREATE DATABASE IF NOT EXISTS invoice_system
#      DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# 2. 配置：复制 backend/.env.example 为 backend/.env，改数据库账号密码

# 3. 装依赖 + 建表（默认只引导一个管理员，不灌演示账号）
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\init_db.py            # 建表 + 引导管理员
.venv\Scripts\python.exe scripts\init_db.py --demo     # 可选：额外灌入演示/验收账号

# 4. 启动（两个终端）
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000   # 终端 A：后端
cd ..\frontend && npm install && npx vite --port 5173 --strictPort                # 终端 B：前端
```

浏览器访问 **<http://localhost:5173>**（Vite 只监听 localhost）。
接口文档 <http://127.0.0.1:8000/docs> ｜ 健康检查 <http://127.0.0.1:8000/api/v1/health>

**账号体系**（默认只引导一个管理员，员工在登录页自助注册）

- `scripts\init_db.py` **默认不灌任何演示账号**，只引导**一个管理员**：用户名取 `.env` 的 `BOOTSTRAP_ADMIN_USERNAME`（默认 `admin`），
  密码取 `BOOTSTRAP_ADMIN_PASSWORD`；**密码留空则随机生成 14 位一次性密码并打印到后端控制台（只显示这一次）**。
- 真实使用流程：管理员登录 → 在「用户管理」创建**财务**账号 → 员工在登录页点「**注册新账号**」自助注册
  （注册者强制为**普通员工**、强制进入「**待分配**」部门，部门决定预算上限，再由管理员调整到实际部门）。
- 登录页另有「**忘记密码？**」：配了 SMTP 就发邮件重置链接（`/reset-password?token=xxx`，30 分钟内有效、只能用一次）；
  **默认没配 SMTP，会落一条「待处理重置申请」，管理员在「用户管理」页顶部一键重置**。

## 说明与限制（摘要，详见 [`项目总览.md`](项目总览.md) §6）

- **OCR 默认仍是 `mock`**（图片哈希派生的假数据，供联调与自动化验收）；切真实识别：`backend/.env` 里 `OCR_PROVIDER=paddle`。
- **费用类别目前仅界面提示必填**，后端预审不强制；**写接口未限流**（需求 5.2 缺项）。
- **OCR 同步执行**：生产部署应改为后台 Worker 进程池消费 `ocr_task` 表。
- **公司主体与部门预算为占位值**，需按真实业务写入。
- **已知偏差**：`/auth/logout`、`/auth/refresh` 未做 CSRF 双提交校验。
- **`scripts/e2e_check.py` 非幂等**（固定发票号），必须在清库后的库上执行；建议用独立库 `DB_NAME=invoice_system_e2e` 跑。
- **安全提示**：演示密码与 `.env` 中的 `JWT_SECRET` 仅供开发使用，正式部署前必须更换；`.env` 与 `backend/storage/` 不入库。
